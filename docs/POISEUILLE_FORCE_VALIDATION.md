# Single-component body-force validation

## Purpose

This benchmark verifies the single-component forcing path by developing a
plane Poiseuille flow from a quiescent fluid. Starting from rest distinguishes
the test from preservation of an already initialized analytical profile: all
streamwise momentum must be generated by the uniform body force passed through
the hydrodynamic kernels.

## Configuration

The tracked `poiseuille_force.inp` case uses:

| Parameter | Value |
|---|---:|
| Domain | `32 x 8 x 32` |
| Non-periodic direction | `x` |
| Flow and force direction | `z` |
| Channel half-width `H` | `15.5` |
| Body force `fz` | `5.0e-5` |
| Kinematic viscosity | `0.1` |
| Initial velocity | `0` |
| Time steps | `10000` |
| Lattice | D3Q27 high-order |
| Precision | double precision |

The planes at `x=1` and `x=32` are solid because `pbc_x=0`; the other two
directions are periodic. Full field output is disabled. The maximum analytical
velocity is `0.06`, corresponding to a moderate lattice Mach number.

### Hydrodynamic wall convention

The regularized boundary reconstruction is applied after the fused
collision/propagation kernel. Missing populations are reconstructed at the
`isfluid=-1` fluid node adjacent to an `isfluid=0` solid node. Although the
discrete fluid/solid link joins nodes `x=1` and `x=2`, this boundary treatment
has its effective no-slip plane at the solid-node coordinate. Therefore this
case uses

```text
xwall,lower = 1,
xwall,upper = Nx,
xc          = (Nx+1)/2,
H           = (Nx-1)/2.
```

For `Nx=32`, the analytical walls are at `x=1` and `x=32`, with `xc=16.5`
and `H=15.5`. This is also the non-`BOUNCE_BACK` convention implemented in
`statistics.f90`. A halfway bounce-back boundary instead uses wall coordinates
`1.5` and `Nx-0.5`, and is not enabled in this benchmark.

## Initialization and forcing

The compile-time selector `POISEUILLESTARTREST` changes only the
single-component Poiseuille initial velocity: it sets all three components to
zero and does not add the random perturbation used by the general Poiseuille
initializer. The original `poiseuille.inp` behavior remains unchanged.

For a single-component build, the moment kernels initialize the local force as

```text
F = (fx, fy, fz),
```

and apply the half-force velocity correction used by the lattice-Boltzmann
forcing scheme. The benchmark enables `POISEUILLE` and
`POISEUILLESTARTREST`, while disabling the two-component, density-ratio, CSF,
and mixed-precision options.

## Analytical solution and error norms

At steady state, the streamwise velocity is

```text
w(x) = fz [H^2 - (x-xc)^2] / (2 nu),
xc = (Nx+1)/2.
H  = (Nx-1)/2.
```

The solver averages the numerical velocity over every `y-z` plane and writes
the numerical and analytical profiles to `plot_poiseuille.dat`. The Python
driver independently constructs the analytical parabola from the input values;
it does not use the analytical column as its reference. It also reports the
maximum difference between its independently calculated values and the values
written by `statistics.f90`. The remaining outputs are the centerline error,
relative L2 error, relative maximum error, and absolute maximum error.

## Automated build, run, and analysis

From the repository root, run:

```bash
python3 run_poiseuille_force_validation.py
```

The script configures the required macros, performs a clean CC 8.0 build,
runs in `poiseuille_force_validation_run/`, and writes
`poiseuille_force_validation_summary.csv`.

Useful alternatives are:

```bash
python3 run_poiseuille_force_validation.py --force
python3 run_poiseuille_force_validation.py --skip-build
python3 run_poiseuille_force_validation.py \
  --skip-build --skip-run --output poiseuille_force_validation_run
```

After building, the script leaves `defines.h` consistent with the generated
Poiseuille executable.
